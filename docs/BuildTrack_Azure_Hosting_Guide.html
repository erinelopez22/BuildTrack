11. Step 9: Custom Domain (Optional)

Azure Static Web Apps (free tier) supports custom domains with free SSL.

  1. Buy a domain (e.g., buildtrack.com from Namecheap/GoDaddy, ~$12/year)
  2. In your Static Web App, go to "Custom domains"
  3. Click "+ Add"
  4. Enter your domain name
  5. Add the CNAME record at your domain registrar pointing to the Static Web App URL
  6. Azure auto-generates a free SSL certificate
Note: The App Service F1 (backend) does NOT support custom domains. Your backend will always be at buildtrack-api.azurewebsites.net. This is fine — users never see the backend URL directly.

14. Troubleshooting

Problem: Frontend loads but login fails / API errors

Check these:
  1. Is VITE_API_BASE_URL set correctly in Static Web App environment variables?
  2. Is Cors__AllowedOrigins set to your exact Static Web App URL (including https://)?
  3. Did you redeploy the frontend after adding the environment variable?
  4. Check App Service logs: az webapp log tail --resource-group BuildTrack-RG --name buildtrack-api

Problem: "Error 500" or database connection fails

Check these:
  1. Is the connection string correct? Check server name, database name, username, password.
  2. Did you set "Allow Azure services" to Yes in the SQL Server firewall?
  3. Is the connection string type set to SQLAzure (not SQLServer)?

Problem: Static Web App shows "404" on page refresh

Fix: Create a file staticwebapp.config.json in your project root: 
{
  "navigationFallback": {
    "rewrite": "/index.html",
    "exclude": ["/assets/*", "/api/*"]
  }
}
Commit and push. This tells Azure to route all paths to index.html (SPA routing).

Problem: Backend is slow / takes 30 seconds to load

This is normal on F1 Free tier. The app sleeps after ~20 minutes of inactivity. The first request "wakes it up" (cold start), which takes 15–30 seconds. Subsequent requests are fast. To avoid this, upgrade to B1 Basic ($13/month) which has "Always On".

Problem: Output location "build" fails deployment

Fix: Change the output location to dist in the GitHub Actions workflow file. Open .github/workflows/azure-static-web-apps-*.yml in your repo and change output_location: "build" to output_location: "dist".
