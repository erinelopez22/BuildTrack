1. System Overview & Architecture

BuildTrack is a full-stack construction inventory management system designed for tracking materials, purchase orders, equipment, and project progress. It supports multi-company tenancy, role-based access, and real-time notifications.

High-Level Architecture

┌────────────────────┐     HTTP/REST     ┌─────────────────────────┐
│   React Frontend   │ ◄──────────────► │  ASP.NET Core 8 API     │
│   (Vite + TS)      │                   │  Controllers → Services │
│   Port: 8080       │     SignalR       │  Port: 5069             │
│                    │ ◄──────────────► │  Hubs/NotificationHub   │
└────────────────────┘                   └────────────┬────────────┘
                                                      │ EF Core
                                                      ▼
                                         ┌─────────────────────────┐
                                         │   Microsoft SQL Server   │
                                         │   (SQLEXPRESS)           │
                                         └─────────────────────────┘

Key Design Decisions

  • API-First: Complete REST API with standardized ApiResponse<T> envelope
  • JWT Authentication: Stateless auth with access + refresh token rotation
  • Multi-Tenant: All data scoped by CompanyId at the service layer
  • SignalR + Polling: Real-time notifications with 30-second polling fallback
  • Role-Based: 18 roles with 7 authorization policies

4. Getting Started — Setup Tutorial

Prerequisites

  • .NET 8 SDK
  • Node.js 18+ and npm
  • SQL Server Express (or full edition)
  • Git

Step 1: Clone the Repository

git clone <repository-url>
cd stockwell-build

Step 2: Configure the Database

Edit backend/BuildTrack.API/appsettings.json:

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=BuildTrackDB;Trusted_Connection=true;TrustServerCertificate=true;"
  },
  "Jwt": {
    "Key": "YourSecretKeyHere_MustBeAtLeast32Characters!",
    "Issuer": "BuildTrack.API",
    "Audience": "BuildTrack.Client",
    "ExpirationMinutes": 60
  },
  "Cors": {
    "AllowedOrigins": "http://localhost:8080,http://localhost:5173"
  }
}
Note: The database and tables are created automatically on first run via EF Core auto-migration in Program.cs. A default super_admin user (admin@buildtrack.com / Admin@123456) is seeded if no users exist.

Step 3: Start the Backend

cd backend/BuildTrack.API
dotnet restore
dotnet run

The API will start on http://localhost:5069.

Step 4: Start the Frontend

# From project root
npm install
npm run dev

The frontend will start on http://localhost:8080.

Step 5: Verify

  1. Open http://localhost:8080 in your browser
  2. Log in with admin@buildtrack.com / Admin@123456
  3. You should see the Dashboard page

8. Authentication & Authorization

JWT Token Flow

1. Client → POST /api/auth/login { loginId, password, companyId? }
2. Server validates credentials, generates tokens
3. Server → { accessToken (60min), refreshToken (7 days), user session }
4. Client stores tokens in localStorage (bt_access_token, bt_refresh_token)
5. Client sends Authorization: Bearer {accessToken} on every request
6. On 401 → Client calls POST /api/auth/refresh automatically
7. If refresh fails → Redirect to /login

JWT Claims

// JwtService.cs generates these claims:
new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
new Claim(ClaimTypes.Email, user.Email),
new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),
new Claim(JwtRegisteredClaimNames.Iat, now.ToUnixTimeSeconds().ToString()),
new Claim(ClaimTypes.Role, role),          // One per role
new Claim("CompanyId", user.CompanyId.ToString())  // Company scoping

Extracting Current User in Services

// Common pattern in all services:
private Guid GetCurrentUserId(ClaimsPrincipal user)
{
    var claim = user.FindFirst(ClaimTypes.NameIdentifier);
    return Guid.Parse(claim!.Value);
}

private Guid? GetCurrentCompanyId(ClaimsPrincipal user)
{
    var claim = user.FindFirst("CompanyId");
    return claim != null ? Guid.Parse(claim.Value) : null;
}

private bool IsSuperAdmin(ClaimsPrincipal user)
{
    return user.IsInRole("super_admin");
}

10. API Client & Data Flow

Core API Client (src/lib/apiClient.ts)

// Base configuration
const API_BASE = import.meta.env.VITE_API_BASE_URL || 'http://localhost:5069';

// Generic request wrapper
async function request<T>(method, url, data?): Promise<ApiResponse<T>> {
  const token = localStorage.getItem('bt_access_token');
  const headers = { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' };

  const response = await fetch(`${API_BASE}${url}`, { method, headers, body: JSON.stringify(data) });

  if (response.status === 401) {
    // Auto-refresh token, retry once
    const refreshed = await refreshAccessToken();
    if (refreshed) return request(method, url, data); // Retry
    else window.location.href = '/login';             // Redirect
  }

  return response.json();
}

// Convenience methods
const get = <T>(url) => request<T>('GET', url);
const post = <T>(url, data) => request<T>('POST', url, data);
const put = <T>(url, data) => request<T>('PUT', url, data);
const del = <T>(url) => request<T>('DELETE', url);

public class NotificationHub : Hub
{
    public override async Task OnConnectedAsync()
    {
        var userId = Context.UserIdentifier;

// Sending notifications from any service:

Token Authentication for SignalR

// Program.cs - JWT events for SignalR
options.Events = new JwtBearerEvents
{
    OnMessageReceived = context =>
    {
        var accessToken = context.Request.Query["access_token"];
        var path = context.HttpContext.Request.Path;
        if (!string.IsNullOrEmpty(accessToken) && path.StartsWithSegments("/hubs"))
        {
            context.Token = accessToken;
        }
        return Task.CompletedTask;
    }
};

// 3. Match order items to quotation items:

Quotation Change Request Workflow

1. User creates change request (add/modify/remove items)
   → Payload stored as JSON
   → Status: "pending"

2. Office Admin reviews
   → Approve: changes applied to quotation
   → Reject: remarks returned to requester
   → Status: "approved" or "rejected"

Asset Borrowing Flow

1. User requests borrow: asset, quantity, expected return date
2. System checks available qty (total - currently borrowed)
3. BorrowTransaction created with status "Borrowed"
4. Asset available count decremented

5. User returns (partial or full):
   → returnedQty updated
   → If fully returned → status "Returned"
   → If partial → status "Partially Returned"

// Service layer pattern (e.g., ProjectService.GetAllAsync):
public async Task<List<ProjectDto>> GetAllAsync(ClaimsPrincipal user, ...)
{
    var companyId = GetCurrentCompanyId(user);
    var isSuperAdmin = IsSuperAdmin(user);

    var query = _db.Projects.AsQueryable();

    // Company scoping: super_admin sees all, others see own company only
    if (!isSuperAdmin && companyId.HasValue)
    {
        query = query.Where(p => p.CompanyId == companyId.Value);
    }

    // ... apply other filters
    return await query.Select(p => MapToDto(p)).ToListAsync();
}

17. Troubleshooting & Common Issues

API Response Unwrapping

Common Bug: Forgetting to unwrap ApiResponse.
Wrong: const data = await projectsApi.getAll(); setProjects(data || []);
Right: const result = await projectsApi.getAll(); setProjects(result.data || []);

Null Coalescing vs OR

Common Bug: Using ?? when value can be 0.
item.quantityReceived ?? item.quantityOrdered returns 0 if quantityReceived is 0.
Use || if you want to fall through on 0: item.quantityReceived || item.quantityOrdered

CamelCase vs snake_case

Common Bug: .NET API returns camelCase (startDate, quantityOrdered), but some code expects snake_case (start_date, quantity_ordered).
Always use camelCase when working with API response data.

CORS Issues

Fix: Ensure appsettings.json has your frontend URL in Cors:AllowedOrigins. Both http://localhost:8080 and http://localhost:5173 are configured by default.

SignalR Connection Failures

Graceful Degradation: The frontend falls back to 30-second REST polling if SignalR WebSocket connection fails. Check browser console for connection errors.

Database Migration

Auto-migration: Program.cs runs db.Database.Migrate() on startup. New columns/tables added via inline migration code in the startup sequence. Check the seeding section in Program.cs for column additions.

Token Refresh Loop

Issue: If the refresh token is also expired, the client enters a redirect loop to /login.
Fix: The API client deduplicates refresh requests and redirects after a single failed refresh attempt.
