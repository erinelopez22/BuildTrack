10. Step 8: Configure & Start Backend Service

8
Create a Systemd Service for Auto-Start

This makes your backend start automatically when the server boots and restart if it crashes.

VM Terminal — Create Service File
ubuntu@buildtrack:~$ sudo nano /etc/systemd/system/buildtrack.service

Paste this content (press Ctrl+Shift+V to paste in terminal):

[Unit]
Description=BuildTrack API
After=network.target mssql-server.service

[Service]
WorkingDirectory=/var/www/buildtrack-api
ExecStart=/usr/bin/dotnet /var/www/buildtrack-api/BuildTrack.API.dll
Restart=always
RestartSec=10
SyslogIdentifier=buildtrack-api
User=www-data

# === EDIT THESE VALUES ===
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=ASPNETCORE_URLS=http://localhost:5069
Environment=ConnectionStrings__DefaultConnection=Server=localhost;Database=BuildTrackDB;User Id=sa;Password=YourStr0ngP@ssword!;TrustServerCertificate=true;
Environment=Jwt__Key=YourSuperSecretKeyAtLeast32CharactersLong!!
Environment=Jwt__Issuer=BuildTrack.API
Environment=Jwt__Audience=BuildTrack.Client
Environment=Jwt__ExpirationMinutes=60
Environment=Cors__AllowedOrigins=https://your-app.vercel.app

[Install]
WantedBy=multi-user.target
Replace these values:
  • Password= — Your SQL Server SA password from Step 4
  • Jwt__Key= — Any random string, at least 32 characters
  • Cors__AllowedOrigins= — Your Vercel URL (you'll get this in Step 11, update later)

Save the file: Press Ctrl+X, then Y, then Enter.

VM Terminal — Start the Service
# Enable auto-start on boot ubuntu@buildtrack:~$ sudo systemctl enable buildtrack Created symlink ... → buildtrack.service # Start the service now ubuntu@buildtrack:~$ sudo systemctl start buildtrack # Check if it's running ubuntu@buildtrack:~$ sudo systemctl status buildtrack ● buildtrack.service - BuildTrack API Active: active (running) # Check the logs if something went wrong ubuntu@buildtrack:~$ sudo journalctl -u buildtrack -f

11. Step 9: Configure Nginx Reverse Proxy

9
Set Up Nginx to Forward Requests to .NET
VM Terminal — Configure Nginx
# Remove default config ubuntu@buildtrack:~$ sudo rm /etc/nginx/sites-enabled/default # Create BuildTrack config ubuntu@buildtrack:~$ sudo nano /etc/nginx/sites-available/buildtrack

Paste this Nginx configuration:

server {
    listen 80;
    server_name 129.154.52.187;  # Replace with YOUR VM's public IP

    # Increase max upload size (for file/evidence uploads)
    client_max_body_size 50M;

    location / {
        proxy_pass http://localhost:5069;
        proxy_http_version 1.1;

        # Required for SignalR WebSockets
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Forward real client info
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeouts for long-running requests
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}
VM Terminal — Enable & Test Nginx
# Enable the config ubuntu@buildtrack:~$ sudo ln -s /etc/nginx/sites-available/buildtrack /etc/nginx/sites-enabled/ # Test the config for syntax errors ubuntu@buildtrack:~$ sudo nginx -t nginx: configuration file /etc/nginx/nginx.conf test is successful # Restart Nginx ubuntu@buildtrack:~$ sudo systemctl restart nginx

12. Step 10: Open Firewall Ports

10
Open Ports on VM and Oracle Cloud

You need to open ports in two places: the VM's firewall AND Oracle Cloud's Security List.

10a: VM Firewall (iptables)

VM Terminal — Open Firewall Ports
# Open port 80 (HTTP) ubuntu@buildtrack:~$ sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT # Open port 443 (HTTPS - for future SSL) ubuntu@buildtrack:~$ sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT # Save rules so they persist after reboot ubuntu@buildtrack:~$ sudo apt install -y iptables-persistent ubuntu@buildtrack:~$ sudo netfilter-persistent save

17. Troubleshooting

Problem: Can't access the API from browser

Check these in order:
  1. Is the backend running? sudo systemctl status buildtrack
  2. Is Nginx running? sudo systemctl status nginx
  3. Did you open ports in Oracle Cloud Security List? (Step 10b)
  4. Did you open ports in VM firewall? (Step 10a)
  5. Check logs: sudo journalctl -u buildtrack -f

Problem: Frontend shows "Network Error" or CORS error

Fix: Make sure the Cors__AllowedOrigins in your service file matches your exact Vercel URL (including https://). Then restart: sudo systemctl daemon-reload && sudo systemctl restart buildtrack

Problem: SQL Server won't start (not enough memory)

Fix: The 1GB VM is tight. Add swap space: 
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
This adds 2GB of swap (uses disk as extra memory). Restart SQL Server after.

Problem: Backend crashes after running a while

Fix: The systemd service has Restart=always which auto-restarts on crash. If it keeps crashing, check memory with free -h and add swap if needed.

Problem: "Shape VM.Standard.E2.1.Micro not available"

Fix: Always Free shapes are limited per region. Try:
  • Wait a few hours and try again (capacity fluctuates)
  • Try a different Availability Domain in the same region
  • Use the ARM shape VM.Standard.A1.Flex (also Always Free, 4 CPUs + 24GB RAM total, much more powerful!)
